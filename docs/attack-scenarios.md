# Сценарии атак и детектирование

Все сценарии выполняются **только на своих ВМ** в изолированной host-only сети лаборатории.
Для каждого указаны техника MITRE ATT&CK, правило Wazuh и рекомендации по устранению.

## Топология

| Узел | Роль | Сеть |
|---|---|---|
| wazuh-manager | Менеджер + Dashboard (wazuh-docker) | 192.168.56.10 |
| win10-agent | Жертва Windows + Sysmon | 192.168.56.20 |
| ubuntu-agent | Жертва Linux + UFW | 192.168.56.30 |
| kali | Атакующий | 192.168.56.100 |

## Сценарий 1. Разведка: сканирование портов

- **Техника:** T1046 (Network Service Discovery)
- **Действие:** SYN-скан Nmap по Linux-агенту.
- **Цепочка детекта:** UFW пишет блоки в `/var/log/ufw.log` → `soclab portscan` в режиме
  `--follow` собирает попытки в скользящем окне и при превышении порога пишет JSON-алерт →
  Wazuh читает JSON (`localfile json`) → правило **100106**.
- **Срабатывание:** вертикальный скан — 15+ портов одного хоста за 60с; горизонтальный —
  один порт на 10+ хостах.
- **Устранение:** ограничить доступ по сети (security groups/UFW), скрыть неиспользуемые
  сервисы, включить rate limiting; при внешнем источнике — блок на периметре.

## Сценарий 2. Доступ к учётным данным: брутфорс SSH

- **Техника:** T1110.001 (Password Guessing)
- **Действие:** перебор пар логин/пароль по SSH.
- **Цепочка детекта:** sshd пишет «Failed password» → штатное правило Wazuh 5760 →
  частотное правило **100100** (8+ неудач с одного IP за 120с, `same_srcip`).
- **Устранение:** запретить вход root по паролю (`PermitRootLogin no`,
  `PasswordAuthentication no`), ключи вместо паролей, fail2ban, MFA.

## Сценарий 3. Исполнение: закодированная команда PowerShell

- **Техника:** T1059.001 (PowerShell), T1027 (Obfuscated Files or Information)
- **Действие:** запуск `powershell.exe -EncodedCommand <base64>`.
- **Цепочка детекта:** Sysmon Event 1 → поле `commandLine` → правило **100101**.
- **Устранение:** Constrained Language Mode, Script Block Logging, AppLocker/WDAC,
  запрет запуска PowerShell обычным пользователям.

## Сценарий 4. Доступ к учётным данным: дамп LSASS

- **Техника:** T1003.001 (LSASS Memory)
- **Действие:** обращение к памяти `lsass.exe` утилитой дампа.
- **Цепочка детекта:** Sysmon Event 10 (ProcessAccess) → `grantedAccess` с правами на
  чтение памяти → правило **100103**; строки в стиле известных утилит — правило **100102**.
- **Устранение:** Credential Guard, защита LSASS (RunAsPPL), ограничение прав отладки
  (SeDebugPrivilege), EDR на блокировку доступа к LSASS.

## Сценарий 5. Закрепление

- **Техники:** T1547.001 (Registry Run Keys), T1053.005 (Scheduled Task)
- **Действие:** запись в ключ `...\CurrentVersion\Run`; создание задачи через `schtasks /create`.
- **Цепочка детекта:** Sysmon Event 13 → правило **100104**; Sysmon Event 1 → правило **100105**.
- **Устранение:** контроль автозапуска (Autoruns), ограничение прав на изменение
  задач/реестра, алерт на изменения автозапуска вне окон обслуживания.

## Как проверить правило без атаки

```bash
# На менеджере: подать событие в движок и увидеть, какое правило сработало
/var/ossec/bin/wazuh-logtest
# вставить сырую строку лога и нажать Enter
```
